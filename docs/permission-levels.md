# 会话权限级别

新建对话和会话设置均可选择，旧会话默认“仅重要操作批准”。设置随会话保存。

| 操作 | 逐项批准 | 仅重要操作批准 | 完全批准 |
| --- | --- | --- | --- |
| 项目内读取、搜索、查看 Git 状态 | 自动 | 自动 | 自动 |
| 项目内创建、精确编辑、移动、复制 | 请求批准 | 自动 | 自动 |
| 常规测试、构建、语法检查命令 | 请求批准 | 自动 | 自动 |
| 删除、Git 恢复/提交/创建分支、终端交互 | 请求批准 | 请求批准 | 自动 |
| 安装、推送、未在常规命令名单内的命令 | 请求批准 | 请求批准 | 自动 |
| 文件工具访问项目外未授权路径 | 仍需路径授权 | 仍需路径授权 | 仍需路径授权 |

权限级别不扩大任务意图。“只分析”“不运行命令”等限制优先于自动批准。
模型正常提出工具调用，由执行层检查，不要求模型猜测何时弹窗。
手动点击 Git 面板的提交等按钮属于用户直接操作，不是模型自主发起的动作。

## 批准与恢复

- 本次允许：批准当前精确动作，消费后失效，不默默保存为永久命令权限。
- 本会话允许相同操作：仅复用相同参数的动作；内容或目标改变需重新判断。
- 拒绝：不执行待批准动作。
- 修改权限级别时清除已缓存的动作/命令批准。
- 旧的路径授权覆盖该路径及子项、持续本会话；弹窗需明确显示这一点。
- 批量工具逐个检查，遇到未批准动作暂停；批准后重新检查任务限制再执行。

## 安全边界

这是一层应用批准策略，不是操作系统沙箱。测试脚本、构建脚本乃至普通程序都可能有副作用。
完全批准可执行任意任务内命令，应仅用于可信项目；命令启动的子进程不会因工作目录位于项目内而被操作系统限制在该目录。
文件工具仍保留路径检查、精确匹配和禁止覆盖已有文件等原有保护。

## 手工验收

分别在三种模式的新对话中要求：

1. “创建 permission_probe.txt，内容为 ok，不运行命令。”逐项批准应弹窗，其余自动；任何模式都不应运行验证命令。
2. “执行 python -m pytest -q。”逐项批准弹窗，其余常规测试自动。
3. “删除 permission_probe.txt。”前两档弹窗，完全批准自动。只用这个临时文件测试。
4. 在逐项批准中拒绝创建文件，确认文件没有生成；再批准一次，确认仅执行一次。
5. 保存设置并重启，检查模式保留；切换模型不应把权限模式重置。

自动回归：`python -m pytest tests/test_permission_modes.py tests/test_studio.py -q`。
