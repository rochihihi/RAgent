# RAgent 产品与技术路线图

## 当前基线

- 当前版本：`v0.2.0`
- 版本定位：Initial Stable（初步稳定版）
- 产品形态：支持 OpenAI、OpenAI 兼容中转和 DeepSeek 的本地桌面编码 Agent
- 已具备能力：多轮会话、仓库文件浏览、代码编辑、命令执行、权限审批、测试验证、Diff、Checkpoint/Resume、调用诊断和桌面 EXE

`v0.2.0` 已经能够完成受控的代码修改任务，但距离 Codex 等成熟编码 Agent 仍有明显差距。后续开发不再以零散 UI 修补为主，而是优先建设可靠的任务循环、原生工具协议、上下文系统和真实执行验证。

## 核心设计原则

1. **行动必须可验证**：不能把“命令已发送”当作“程序已打开”，也不能把“文件已修改”当作“任务已完成”。
2. **失败必须改变策略**：工具失败、模型超时或验证失败后，应诊断原因并选择新路径，不能机械重复动作。
3. **权限必须可理解**：每一次审批都应清楚说明具体目的、影响范围、风险和批准后发生的事情。
4. **上下文必须节制**：优先检索相关代码和增量变化，不反复发送完整仓库与全部历史。
5. **模型与执行器解耦**：模型负责决策，确定性工具负责执行和验证，供应商差异由适配层处理。
6. **真实记录，不伪造结果**：明确区分模型回复、工具结果、进程状态、窗口状态和测试证据。

## v0.3.0 — Claude Code 式工作流与可验证 Agent Core

目标：吸收 Claude Code 的精简交互和连续工作流，把 RAgent 从“模型加工具界面”升级为能够持续完成任务的可靠执行型 Agent；同时保留可验证、可追溯的产品差异。

### v0.3.0 首批交付范围

#### 1. 精简回答

- 默认只汇报“完成结果、验证证据、Git 状态或待处理问题”。
- 常规工具调用和成功日志放入时间线，不在聊天区重复堆叠。
- 提供“精简 / 标准 / 教学”三种回答模式，项目级保存选择。
- 任务结束摘要必须链接到实际 Diff、测试结果和提交记录。

#### 2. `RAGENT.md` 项目规则

- 打开项目时自动发现并读取根目录下的 `RAGENT.md`。
- 支持编码规范、验证命令、禁止操作和 Git 提交要求。
- UI 显示规则文件来源、已应用条数和解析错误，不静默忽略。
- 项目规则作为高优先级上下文，但不能绕过权限和安全约束。

#### 3. 计划、执行与自动模式

- **计划模式**：只读分析仓库并生成方案，不修改文件、不执行有副作用的命令。
- **执行模式**：允许编辑和验证，敏感操作仍需逐项授权。
- **自动模式**：在项目权限范围内连续执行，遇到越权、破坏性操作或方案分歧时暂停。
- 当前模式在页面顶部持续可见，切换时明确说明能力变化。

#### 4. 文件 Checkpoint 与撤销

- 每轮文件修改前保存独立 checkpoint，不依赖仓库已初始化 Git。
- 支持撤销本轮修改、恢复单个文件和恢复到某次验证通过状态。
- 恢复前展示影响文件和当前未保存变更，防止覆盖用户编辑。
- checkpoint 与会话、任务步骤和验证证据关联。

#### 5. 自动验证状态

- 根据项目文件和 `RAGENT.md` 自动发现测试、静态检查和格式化命令。
- 任务结束时显示“已验证 / 部分验证 / 未验证 / 验证失败”。
- 每条结论保存实际命令、工作目录、退出码、运行时间和关键输出。
- 未运行验证时必须说明原因，禁止用“已完成”暗示已通过测试。

### v0.3.0 底层支撑项

#### 6. 原生工具调用协议

- OpenAI 优先使用原生 Function Calling / Tool Calling。
- DeepSeek 使用其支持的工具调用协议。
- 每个工具提供独立、严格的 JSON Schema。
- 同一次模型响应允许包含解释、一个或多个工具调用及后续决策。
- 中转站不支持原生工具协议时，自动降级到兼容 JSON 协议。
- 记录实际使用的协议、降级原因和响应解析结果。
- 非法参数由控制器修复或反馈给模型，避免直接终止整个任务。

#### 7. 可靠任务循环

- 自动区分普通问答、代码修改、运行程序、安装依赖和系统操作。
- 将用户目标拆成数量可变的可执行计划，不固定为五步。
- 每一步明确前置条件、完成证据、失败原因和下一步。
- 用户发送“继续”时恢复未完成目标，而不是重复上一动作。
- 工具失败后生成新的诊断步骤，禁止无变化重试。
- 安装依赖后自动检查版本并继续原任务。
- 模型调用中断后从最后一个已确认状态恢复。

#### 8. 真实结果检测

- 区分命令已提交、进程已创建、进程仍运行、窗口已出现和窗口已关闭。
- Windows GUI 程序启动后检测进程、主窗口句柄和窗口标题。
- 打开文件时验证关联程序或浏览器确实启动。
- 测试任务必须保存退出码、标准输出、失败用例和运行时间。
- 完成任务前检查用户原始要求是否全部满足。
- 缺少证据时使用“已执行但未确认”，禁止宣称成功。

#### 9. 标准工具集

- 文件：读取、搜索、创建、精确编辑、移动、复制和受控删除。
- 代码：符号搜索、引用查找、语法检查、格式化和测试。
- Git：状态、Diff、提交历史、分支、提交和安全回滚。
- 系统：进程查询、窗口检测、启动、关闭和聚焦应用。
- 环境：依赖检测、包管理器识别、安装建议和版本验证。
- 网络：HTTP 探测、DNS/代理诊断、供应商连接检查。
- 所有工具返回结构化结果以及适合用户阅读的中文摘要。

#### 10. 权限体验

- 根据具体动作解释“为什么现在需要这一步”。
- 明确显示命令或路径、影响范围、风险等级和可恢复性。
- 针对读取、写入、删除、联网、安装、启动程序分别生成说明。
- 支持“拒绝”“调整方案”“本次允许”和“本项目始终允许”。
- 同一任务链中已批准的等价操作不重复弹窗。
- 调整方案后重新规划，并继续原目标。
- 权限窗口内容可滚动，操作按钮始终可见。

#### 11. 动态预算

- 普通回答不消耗工具步骤预算。
- 每个子目标单独计算预算。
- 有实际进展时允许自动扩展预算。
- 只有连续无进展、成本超限或明确失败时才暂停。
- UI 展示当前目标、正在进行的步骤、已完成事项和等待原因。

### v0.3.0 验收标准

- 默认精简模式仅显示结果、验证和待处理问题，详细过程可从时间线查看。
- 新项目和已有项目都能读取 `RAGENT.md`，规则应用状态可见。
- 计划模式不产生文件或系统副作用，执行和自动模式严格遵守权限边界。
- 在未初始化 Git 的新文件夹中也能创建 checkpoint 并完整撤销本轮修改。
- 完成摘要显示准确验证状态，且可查看命令、退出码和关键输出。
- 固定任务集中不再发生连续重复读取或重复执行。
- 用户说“继续”后能够恢复正确的未完成步骤。
- GUI 启动结果能够通过进程和窗口证据确认。
- 原生工具调用、兼容协议和协议降级均有自动化测试。
- 权限批准后只执行一次，弹窗自动关闭并继续任务。
- 模型超时、HTTP 502、非法 JSON 和工具错误均可恢复。
- 完整测试、Ruff、mypy、前端类型检查和打包检查通过。

## v0.4.0 — Repository Intelligence

目标：提升大型代码库理解能力，同时降低延迟与 Token 消耗。

### 主要工作

- 建立增量代码索引，记录文件、语言、模块、类、函数和引用关系。
- 使用 AST 与文本检索联合召回相关代码。
- 根据 Issue、错误堆栈、测试失败和 Git Diff 排序上下文。
- 修改后只重新读取受影响符号和依赖区域。
- 自动压缩旧对话，保留用户约束、已确认事实、失败证据和待办事项。
- 提供项目结构、调用关系和变更影响分析。
- 支持多文件重构和跨模块验证。

### 验收标准

- 中型仓库首轮上下文不需要发送完整文件树。
- 连续任务能够保留关键约束而不重复询问。
- 相同任务平均输入 Token 和完成时间相较 `v0.3.0` 明显下降。
- 多文件任务能够给出准确的修改范围和回归测试建议。

## v0.5.0 — Developer Workflow

目标：形成可长期日常使用的桌面开发工作台。

### 主要工作

- 流式展示模型回复、终端输出和工具进度。
- 支持任务暂停、取消、恢复和后台执行。
- 增加项目级权限规则管理。
- 增加完整 Git 工作流：创建分支、生成提交、比较 Diff 和准备 PR 描述。
- 引入可扩展工具/插件注册机制。
- 支持自定义模型配置、超时、重试和代理策略。
- 增加崩溃恢复、数据库迁移和自动备份。
- 提供诊断中心，展示供应商、模型、协议、请求 ID、延迟、HTTP 状态和降级原因。

### 验收标准

- 长任务运行期间用户始终能看到当前活动和实时输出。
- 关闭并重新打开应用后可恢复未完成任务。
- 能明确判断一次失败来自 Agent、执行器、网络、中转站还是模型供应商。
- 插件工具不能绕过权限和审计系统。

## v1.0.0 — Production Ready

目标：达到可公开展示、稳定分发和技术审查的完整产品状态。

### 发布要求

- 建立覆盖问答、修复、重构、创建项目、安装依赖和启动 GUI 的固定 Benchmark。
- 输出成功率、平均步骤、耗时、Token、失败类型和恢复率。
- 在至少两个真实模型供应商上完成评测，不使用脚本模型冒充模型能力。
- 关键状态机、权限、工具和恢复逻辑具有高覆盖率自动化测试。
- 提供 Windows 安装包、卸载流程、自动更新和版本迁移。
- 完成威胁模型、隐私说明、架构文档和故障排查手册。
- GitHub Actions 覆盖测试、静态检查、前端构建、Python 包构建和桌面打包冒烟检查。
- 凭据不进入数据库事件、日志、Git 或错误页面。

## 优先级顺序

### P0：立即实施

1. 精简回答与结果/证据摘要。
2. `RAGENT.md` 项目规则加载与可见状态。
3. 计划、执行与自动三种模式。
4. 不依赖 Git 的文件 checkpoint 与撤销。
5. 自动验证发现与四态结果展示。

### P1：核心增强

1. 原生工具调用与兼容协议降级。
2. 可恢复、避免重复动作的任务循环。
3. 真实进程/窗口结果检测与标准 Git/系统工具。
4. 权限审批去重、执行后自动续跑和动态预算。

### P2：产品化

1. 流式终端与后台任务。
2. 插件机制和项目级权限。
3. Benchmark、安装器和自动更新。
4. 发布文档、演示材料和技术讲解材料。

## 版本交付规则

每个版本发布前必须完成：

1. 更新版本号和发布说明。
2. 运行完整 Python 测试、Ruff、mypy 和前端类型检查。
3. 构建前端和桌面 EXE，并执行启动冒烟测试。
4. 验证至少一个普通问答、一个代码修改和一个需要权限的端到端任务。
5. 创建独立 Git 提交和带说明的版本标签。
6. 推送分支与标签到 GitHub，确认 CI 通过。
